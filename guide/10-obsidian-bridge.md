# Chapter 10: Obsidian Bridge

Your agents run on a VPS, talk to you via Telegram, and store knowledge in a shared brain. But that brain is just markdown files in Dropbox — which means you can connect it directly to Obsidian and get a human-readable window into everything your agents know.

This chapter covers two things: **junctions** (bidirectional links from your vault into the brain) and a **daily briefing** (a file agents push into your vault every morning).

---

## The Hybrid Model

| Layer | Direction | Mechanism |
|-------|-----------|-----------|
| Reference data (people, commitments, tasks) | Bidirectional | Windows junctions from vault into brain |
| Daily state (schedule, agent health, what needs attention) | Agent → You | Briefing file generated by Mr Fixit cron |
| Your intent (TODOs, plans, decisions) | You only | Stays in Obsidian — agents don't read it |

The brain stays the system of record for agent knowledge. Obsidian stays your system of record for thinking. The bridge connects them without merging them.

## Part 1: Junction Bridge

### What gets junctioned

| Vault path | Brain target | Why |
|---|---|---|
| `Brain/People/` | `openclaw-backup/people/` | Family/friend profiles — core graph nodes |
| `Brain/Commitments/` | `openclaw-backup/commitments/` | Promises agents are tracking |
| `Brain/Tasks/` | `openclaw-backup/tasks/` | Action items from agents |
| `Briefings/` | `openclaw-backup/obsidian/briefings/` | Daily briefing files |

### What stays out

- `agents/*.status.md` — legacy per-agent heartbeat files (nothing writes them on a schedule since R3+R6; `fleet-health.json` is the live source)
- `fleet-health.json` — machine-readable fleet snapshot; use the rendered morning brief instead
- `notes/inbox.md` — internal triage state
- `facts/` — verbose, agent-formatted with confidence/decay metadata
- `archive/` — historical, low-signal

### Setup

Your vault must be **outside Dropbox** to avoid double-sync. Junctions point _into_ Dropbox, but the vault root itself should not be a synced folder.

```cmd
mkdir "C:\Users\you\YourVault\Brain"
```

Create junctions (Python, because `mklink /J` from bash is painful on Windows):

```python
import _winapi

junctions = [
    ("C:/Users/you/YourVault/Brain/People",       "E:/Dropbox/openclaw-backup/people"),
    ("C:/Users/you/YourVault/Brain/Commitments",   "E:/Dropbox/openclaw-backup/commitments"),
    ("C:/Users/you/YourVault/Brain/Tasks",         "E:/Dropbox/openclaw-backup/tasks"),
    ("C:/Users/you/YourVault/Briefings",           "E:/Dropbox/openclaw-backup/obsidian/briefings"),
]

for link, target in junctions:
    _winapi.CreateJunction(target, link)
    print(f"OK: {link} -> {target}")
```

Open the vault folder in Obsidian. The junctioned directories appear as native folders.

### Bidirectional writes

Edits in Obsidian flow through the junction into the brain, then sync to VPS via Dropbox. This is safe for **people files** (static, rarely agent-written). Avoid editing `commitments/active.md` or `tasks/queue.md` from Obsidian — agents append to these with strict formatting conventions, and a casual edit could break parsing.

### Wikilinks

When agents populate `people/avery-smith-rivera.md`, you can link to it from anywhere in your vault with `[[avery-smith-rivera]]`. The daily briefing uses these links automatically — names in the schedule and commitments become clickable graph connections.

## Part 2: Daily Briefing

A Python script (no LLM, zero cost) that compiles agent outputs into an Obsidian-native markdown file every morning.

### How it works

1. Mr Fixit's cron fires at 12:10 UTC (5:10 AM PT) — 10 minutes after Mistress Mouse's morning briefing
2. The script reads:
   - Mistress Mouse's cached morning briefing (`~/.openclaw/family-calendar-workspace/cache/morning-briefing.txt`)
   - Fleet health snapshot (`~/Dropbox/openclaw-backup/fleet-health.json`) — post-R3, replaces the old `agents/*.status.md` glob
   - Open commitments (`commitments/active.md`)
   - Open tasks (`tasks/queue.md`)
3. Assembles into markdown with YAML frontmatter and `[[wikilinks]]`
4. Writes to `~/Dropbox/openclaw-backup/obsidian/briefings/YYYY-MM-DD.md`
5. Dropbox syncs to local → appears in Obsidian via the junction

> **Note:** If your `obsidian-briefing/parsers.py` still globs
> `agents/*.status.md`, it's reading stale data. The `.status.md`
> files are a legacy artifact that nothing refreshes on a schedule
> after R3+R6. Point the parser at `fleet-health.json` instead — see
> `agents/fix-it/scripts/morning-status.py` for the pattern.

Silent on success. No Telegram notification — you just open Obsidian and the briefing is there.

### Output format

```markdown
---
date: 2026-04-08
generated_at: 2026-04-08T12:10:00Z
type: daily-briefing
---

# Wednesday, April 8

## Schedule
> From Mistress Mouse's 5:00 AM briefing

Morning
- 👨 9:30–10:00 AM — [[sam-smith|Sam]] / Ashley

Afternoon
- 👨 1:00–2:00 PM — Cleaners arrive

## Agent Status
| Agent | Status | Last Heartbeat |
|-------|--------|---------------|
| 🦊🔧 Mr Fixit | healthy | 12:00 UTC |
| 🐭📅 Mistress Mouse | healthy | 11:55 UTC |

## Open Commitments
- **Bob Martinez** → me: Send revised proposal (by 2026-04-07)

## Open Tasks
- Confirm nanny availability for Thursday (due 2026-04-09)
```

### Script location

```
~/Dropbox/openclaw-backup/scripts/obsidian-briefing/
├── generate.py    # Entry point
├── config.py      # Paths, agent roster, wikilink aliases
├── parsers.py     # Parse morning briefing, status files, commitments, tasks
└── wikilinks.py   # Name → [[slug]] conversion
```

Deployed via Dropbox sync (copy to `E:\Dropbox\openclaw-backup\scripts\obsidian-briefing\` locally, Dropbox syncs to VPS).

### Cron registration

```bash
oc cron add \
  --agent fix-it \
  --name "obsidian-briefing" \
  --cron "10 12 * * *" \
  --to "$TELEGRAM_CHAT_ID" \
  --account "default" \
  --no-deliver \
  --message "Generate daily Obsidian briefing. Run: python3 ~/Dropbox/openclaw-backup/scripts/obsidian-briefing/generate.py. If successful: produce NO output. Update your status file. If it fails: report the error."
```

### Adding new sources

To include data from a new agent (e.g., Hilda's delivery digest), add a parser in `parsers.py`, a section in `generate.py`, and update the tests. The script is intentionally modular — each source is independent, and missing sources degrade gracefully.

## Key lessons

1. **Vault outside Dropbox.** Junctions from a Dropbox path into another Dropbox path causes double-sync. Keep the vault on local disk.
2. **Use `_winapi.CreateJunction()` on Windows.** `mklink /J` from bash/Git Bash is unreliable. Python's `_winapi` works cleanly.
3. **Read-only mindset for brain files.** Browse and search in Obsidian, but edit sparingly. Agents own the write conventions.
4. **Wikilink aliases are manual.** The config maps display names to slugs (`"Avery": "avery-smith-rivera"`). Update it as you add people files.
5. **No LLM in the briefing.** The script is pure I/O — deterministic, zero cost, instant. If you want LLM summaries, that's a different feature.
